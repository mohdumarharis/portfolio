02 — ADVANCED RAG APPPERSONAL PROJECT

Ask your documents.
Inspect the evidence.

A document question-answering app that makes retrieval visible. Ask about PDFs, slide decks or notes, then inspect the source passages, reranker scores and retrieval stages behind the answer.

RETRIEVAL
Dense search + BM25, rank fusion and cross-encoder reranking
EVALUATION
Stage-by-stage recall, MRR and answer / abstention checks
Python / LangChain / Chroma / BM25 / Sentence Transformers / Azure OpenAI
Explore the repository ↗
Read the engineering notes ＋

Two ways to find the evidence

Dense retrieval captures semantic similarity; BM25 catches exact terms. Reciprocal Rank Fusion combines the rankings, and a cross-encoder reranks the pooled passages against the question before Azure OpenAI generates an answer from the selected context.

An index that remembers what changed

A content-hashed file manifest and stable chunk IDs allow incremental indexing: changed files are reprocessed, deleted files are removed, and unchanged documents stay indexed.

Measure each stage

The evaluation harness compares dense, sparse, fused and reranked retrieval against a golden set. Saved baselines make changes to chunking and retrieval measurable; answer checks also include questions the documents cannot answer.

In the checked-in reference run, reranking improved recall over fusion, while BM25 alone outperformed dense retrieval. Those results guide the next iteration rather than becoming a general accuracy claim.

Personal project with a terminal interface. Reranker scores are visible but do not yet filter out weak matches; abstention is instructed in the answer prompt. Evaluation results apply to the reference corpus.

03 — AGENTIC AIPERSONAL PROJECT

Verify the claim.
Keep people in control.

AI Insurance Claim Verification Agent

A multi-agent system that ingests a claim, checks it against policy documents and flags inconsistencies. Deterministic checks and human review gates govern the outcome.

AGENTS
Document parsing, policy verification and fraud triage
REVIEW
Low-confidence and high-value claims go to a human reviewer
LangGraph / Azure OpenAI (direct API) / FastAPI / Python / Pydantic / Docker
Read the system design ＋

A defined graph of responsibilities

LangGraph coordinates specialised agents through explicit state transitions. Document parsing, policy verification and fraud triage each have a defined role in the claim verification workflow.

Rules govern; language models assist

The decision core uses deterministic, auditable rules. LLMs extract information, compare it with policy evidence and generate explanations. Pydantic validates the structured data passed through the system.

Evidence before a decision

PII is masked before LLM calls. Grounding checks compare generated claims against source policy documents, and the system refuses to decide when evidence is insufficient.

A useful handoff to a reviewer

Confidence-based routing sends uncertain or high-value cases to a review queue with a structured summary of completed checks, unresolved questions and supporting evidence. A claim can only clear through a deterministic check or a human gate.

Personal demonstration project. The diagram describes the design; it shows no real claims or policyholder data.
